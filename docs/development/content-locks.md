# コンテンツロック

最終更新: 2026-08-29

## 目的

保存空間、ノートブック、またはノート単位で、Markdown本文を利用者のパスフレーズにより保護する。ロック中は本文を読み書きできず、解除した起動中だけ復号する。

## 対象とUI

- 保存空間: 「設定 > 保存場所」の下部にある各保存空間から設定する。選択中の保存空間がロックされた状態で起動すると、通常のServiceを起動せず解除画面を表示する。
- ノートブック・ノート: 通常画面3ペインの各項目にある編集ポップアップから、名前・タイトルとロックを設定する。
- 一覧: 「設定 > ロック」で、現在設定されているロック、解除状態、パスフレーズ変更、無効化を管理する。
- ノートまたはノートブックを選択する際は、バックエンドが判定した未解除のロックを共通の解除ダイアログで順に要求する。キャンセル時は元の選択を維持し、本文を読み込まない。

保存空間のロックは空間内の全ノートに、ノートブックのロックは子孫ノートブックを含む配下のノートに適用する。ノート自身のロックはそのノートだけに適用する。複数の対象が重なる場合、本文を読むには該当するすべてのロックを解除する必要がある。

## 保存と暗号化

- ノートブック名、ノートタイトル、ID、所属、タグなどのメタデータは平文で保持する。
- Markdown本文はAES-256-GCMで暗号化する。本文ごとに対象IDを認証データへ含めるため、ファイルの差し替え・改ざんは復号時に検出する。
- 各ロックにはランダムな32 byte鍵を作成し、パスフレーズからArgon2idで導出した鍵で包む。パスフレーズと復号鍵は永続化しない。
- 有効化・無効化時は一時ファイル、操作記録、SQLiteトランザクションを用い、起動時に未完了操作を回復する。
- 「今すぐロック」はメモリ上の鍵を破棄し、編集中の本文を保存後に画面から消去する。アプリ終了時にも鍵を破棄する。

## セッション中の自動ロック

- 「設定 > ロック」で、解除後の自動ロック時間を `アプリ終了時のみ（既定）`、`1分`、`5分`、`15分`、`30分`、`60分` から選択できる。
- 各ロックは、解除・有効化・パスフレーズ変更で利用可能になった時点から固定時間で再ロックする。ノート閲覧、編集、マウス操作、キーボード操作では期限を延長しない。
- 設定時間を変更した場合は、すでに解除した時点を基準に期限を再評価する。短い時間へ変更して期限を過ぎていれば直ちにロックする。
- 期限到来時は先に未保存の下書きを保存する。保存に失敗した場合は鍵を破棄せず、安全な警告を表示して短時間後に再試行する。
- アプリ再起動時は常にメモリ上の鍵を失うため、既定の「アプリ終了時のみ」でも再度パスフレーズが必要である。

## 利用制限

- 保護対象の本文は、解除済みの起動中であってもAIコンテキスト、AI履歴、AI成果物に使用しない。
- ロックを設定する対象に既存のAI記録がある場合、件数を表示して明示確認を求める。確認時だけ関連記録を削除する。
- 既存のWebDAV同期先には平文の履歴があるため、ロックの有効化前に同期を切断する。暗号化本文を同期するプロトコルは本スコープに含めないため、本文ロックを持つ保存空間では同期の設定・実行を拒否する。
- 明示的なロック対象やその配下は削除できない。ロックの適用範囲を原子的に再暗号化する仕組みを追加するまで、ロックが設定されている間はノートブック階層の移動と「ノートを残して削除」を拒否する。

## 回復不能性

パスフレーズを忘れた場合、本文を復元する手段はない。ロックを無効化するにも、そのロックのパスフレーズが必要である。
