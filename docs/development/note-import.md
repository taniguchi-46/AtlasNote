# ノートインポート

## 対象範囲

- Markdown（`.md`）、テキスト（`.txt`）、HTML（`.html` / `.htm`）を1ファイル1ノートとして取り込む。
- 保存先は最上位階層、既存ノートブック、新しいトップレベルノートブックから選択する。
- 添付ファイル、画像の保存、ドラッグ＆ドロップは対象外とする。

要求とHTML変換規則は [`scopes/scope-pre-phase5.md`](scopes/scope-pre-phase5.md) を正とする。

## 境界と保存契約

- フロントエンドは保存先とタイトル決定方式だけをWails APIへ渡す。ファイルパスはGo側のOSネイティブ複数選択ダイアログで取得し、フロントエンドへ返さない。
- `internal/noteimport` は読み込み、形式判定、タイトル決定、HTML→Markdown変換だけを担当する。永続化は必ず既存の `note.Service.Create` と `CreateNotebook` を通す。
- これによりMarkdown正本、SQLiteメタデータ、操作journal、FTS・ノートリンク索引、sync outbox、コンテンツロックの既存保証を維持する。
- 同時実行は拒否する。保存空間の切替は、ファイルダイアログ表示中を含むインポート中に拒否する。

## 入力とタイトル

- 文字コードはUTF-8のみとし、UTF-8 BOMは除去する。1ファイルの入力上限は2 MiBで、変換後本文も既存ノート本文上限で検証する。
- `.md` と `.txt` はBOMを除き本文をそのままMarkdown正本として保存する。`.md` 内のraw HTMLは既存の通常ノートと同じ表示時安全化に委ね、インポートで書き換えない。
- タイトルの決定方式は、モーダルを開くたびに初期値「自動」として選択する。選択は保存しない。同一バッチの全ファイルに同じ方式を適用する。

| 選択値 | タイトル候補 | 候補がない場合 |
| --- | --- | --- |
| 自動 | Markdown／テキストは先頭行のATX見出し。HTMLは最初の可視`h1`、`title`、`meta[name="title"]`の順 | ファイル名 |
| ファイル名 | 拡張子を除くファイル名 | `インポートしたノート` |
| 先頭見出し | Markdown／テキストは先頭行のATX見出し。HTMLは最初の可視`h1` | ファイル名 |
| メタデータ | HTMLの`title`、`meta[name="title"]`の順。Markdown／テキストのfront matterは解釈しない | ファイル名 |

- 旧クライアントなどで方式が未指定の場合は「自動」として扱う。未定義の方式は、ファイル読み込み・ノートブック作成・ノート保存より前に `NOTE_IMPORT_INVALID_TITLE_MODE` として拒否する。
- タイトル候補と本文は別に扱う。タイトルに使った見出しやメタデータを本文から除去・書き換えない。タイトルは空白を正規化し、既存の200文字上限へ切り詰める。

## HTML変換

- `golang.org/x/net/html` でDOMとして解析し、ネットワーク取得・スクリプト実行は行わない。
- scopeで許可された見出し、段落、装飾、引用、リスト、チェックリスト、コード、区切り線、単純表、許可URLのリンクだけをMarkdownへ再構築する。
- raw HTML、属性、CSS、コメント、DOCTYPE、危険なURL、外部画像は残さない。画像は`alt`文字列だけを保持する。
- `script`、`style`、`iframe`、フォームなどは内容ごと破棄する。`rowspan`、`colspan`、不均一な列の表は、行ごとのプレーンテキストへフォールバックする。
- `hidden`属性を持つ要素とその子孫は本文・先頭`h1`候補から破棄する。HTMLのboolean属性として属性値は評価せず、`hidden="false"`も非表示として扱う。CSSの`display`／`visibility`、class、`aria-hidden`は評価しない。`head`の`title`と`meta[name="title"]`はメタデータ方式の候補として扱う。
- 欠落タグを含むHTMLはパーサーが許容する範囲で変換する。ただし可視本文も構造要素も生成できないHTMLは空ノートを作成せず、ファイル単位のエラーにする。

## 結果と失敗

- 読み込み・拡張子・文字コード・HTML変換の失敗はファイル単位で記録し、次のファイルを続行する。
- 新規ノートブックは最初に変換可能なファイルを確認してから作成する。全ファイルが変換不能なら作成しない。
- ノート保存に失敗した場合は成功済みノートを保持し、残りのファイルは実行しない。結果には成功・失敗のファイル名だけを返し、フルパスや本文は返却・ログ出力しない。
- 新規ノートブックを作成した後に保存障害が起きた場合、同期済み操作を危険に巻き戻さないため空ノートブックが残る可能性がある。

## ロックと同期

- 既存ノートブックを保存先にする前に、UIは共通コンテンツロック解除フローを通す。Go側の `note.Service` でも最終的にアクセス・暗号化を検証する。
- ロック済みまたは未解除の保存先への保存は拒否され、成功時は既存の継承ルールに従い本文を暗号化する。
- インポート完了後はノート・ノートブック・検索表示を更新し、成功件数が1件以上なら自動同期を予約する。自動ロックの固定期限はインポート操作で延長しない。
