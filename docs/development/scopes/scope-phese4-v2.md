# Phase 4詳細スコープ v2：AI司書・実行体験

最終更新: 2026-07-27

決定状態: 正式決定（2026-07-27）

## 位置付け

本書は、Phase 4 v1（AI設定・単発要約）の後に実装するv2の要求範囲と完了条件を定義する。v1の正本は [`scope-phese4.md`](scope-phese4.md)、v2の作業チェックは [`../../todo/todo-phese4-v2.md`](../../todo/todo-phese4-v2.md) とする。Phase 4全体の完了条件はv3完了であり、v3の範囲は [`scope-phese4-v3.md`](scope-phese4-v3.md) を参照する。

v2では、初期プロバイダーをOpenRouterとGemini APIに限定したまま、AI司書の候補提示と実行中の操作体験を追加する。v2の生成結果と会話は永続化せず、既存のMarkdown正本、SQLite、操作journal、WebDAV outboxをAI処理だけで変更しない。

## 目的

単発要約で確立した送信前確認、秘密情報非露出、revision/CAS、ローカル機能継続の境界を維持しながら、ノートの整理を支援する候補生成を提供する。

## 対象範囲

### 1. AI実行基盤

- OpenRouterとGemini APIのProvider adapterを継続利用する。Groq、OpenAI、Ollama、LM Studioはv2・v3の完了条件に含めない。
- ストリーミングと部分応答を、UI上の一時状態として表示する。
- 利用者によるキャンセルを提供する。キャンセル済みの部分応答は結果として採用せず、ノートへ適用しない。
- タイトル、タグ、分類、関連候補などの用途に限定した構造化出力を受け付け、Provider固有の形式はGo側で正規化する。
- 自動retry、別モデルへの自動切替、別Providerへのfallback、アプリ全体の無制限な同時実行は行わない。
- 既存の入力上限、ログ非露出、safe error、タイムアウト、手動retryの原則を維持する。

### 2. AI司書

- 現在のノートを対象にタイトル候補を生成する。
- タグ候補を生成し、既存タグとの重複を整理して表示する。
- ノートの分類候補を生成する。ノートブック移動やタグ付与は自動実行しない。
- 関連メモ候補を生成する。判定基準、候補なし、低関連度、大量ノート時の扱いを定義する。
- 重複メモ候補を生成する。削除、統合、本文の自動変更は行わない。
- 一度の要求で処理する対象ノートと候補数を明示し、全ノートへの自動バッチ処理は行わない。

### 3. 利用者による適用

- 候補はプレビューしてから、利用者が個別に採用・破棄できる。
- タイトル、タグ、分類、ノートリンクの適用は既存のNote／Tag／Link Serviceを経由する。
- 適用時は現在のrevisionを確認し、保存失敗・競合時は外部結果を適用しない。
- 関連メモ候補を採用してリンクを作る場合も、既存のMarkdownリンク・索引更新・保存laneの契約を維持する。
- AI結果をノート本文へ自動追記しない。

### 4. 保存・同期境界

- AIの候補、途中応答、プロンプト、生成結果、会話履歴は画面上の一時状態だけに保持する。
- v2ではAI用のSQLite entity、schema、migration、操作journal、検索索引、WebDAV entity、outboxを追加しない。
- AI処理が失敗しても、通常のローカル保存・編集・検索・既存WebDAV同期を継続する。

### 5. UI・アクセシビリティ

- 生成中、部分応答、キャンセル、成功、失敗、空結果、stale、競合の状態をinlineで表示する。
- キャンセル、採用、破棄、再試行をキーボードで操作できるようにする。
- 本文、プロンプト、生成結果、API Key、raw provider errorを通知・ログへ出さない。

## 対象外

- メモQ&A、RAG検索、アイデア壁打ち、ブレインストーミング
- プロンプト生成・改善、README・ドキュメント・ブログ・要件定義の生成
- チャット履歴、要約、候補、執筆結果の永続化
- AIデータのWebDAV同期
- Groq、OpenAI、Ollama、LM StudioのProvider追加
- AIエージェント、添付ファイル、外部サービス連携

## 完了条件

- AI司書5機能と関連メモ4項目の仕様・実装・テストが完了している。
- ストリーミング、部分応答、キャンセル、構造化出力の成功・失敗・中断をtest doubleで検証できる。
- 採用操作だけが既存のrevision/CAS・保存laneを通り、未採用・失敗・競合結果が保存されない。
- AI処理の前後でMarkdown、SQLite、操作journal、検索索引、WebDAV outboxが不正に変化しない。
- 実キーなしのGo／Frontend／CI／手動受け入れが成功している。

## 既存契約との関係

- Markdown本文を正本とする。
- AI候補の適用は既存のNote／Tag／Link ServiceとCASを通す。
- Phase 3 WebDAVのformat、manifest、object、entity、schema version、migration、競合契約は変更しない。
