## 目的

Phase 5へ進む前に、将来的な機能として整理していた項目から実装対象を確定し、実装順序と設計上の未確定事項を明確にする。

## 実装確定機能

以下の7機能を実装対象とする。

1. ノート保存空間の分割
2. ロック機能
3. md・txt・HTMLからインポート
4. HTMLエクスポート
5. PDFエクスポート
6. グローバルショートカット
7. 自動バックアップ・バックアップ復元

## 実装順序

データ構造・安全性への依存関係を踏まえ、次の順で進める。

1. ノート保存空間の分割
2. ロック機能
3. md・txt・HTMLからインポート
4. HTMLエクスポート
5. PDFエクスポート
6. グローバルショートカット
7. 自動バックアップ・バックアップ復元

## 共通方針

- ノート本文の正本は Markdown とし、SQLite はメタデータおよび派生インデックスとして扱う。
- 既存の `expectedRevision` / CAS、ノート操作キュー、単一書き込み、ジャーナル・回復処理を維持する。
- フロントエンドのコンポーネントから Wails のファイル API を直接呼ばず、既存の API クライアント・Wails・Service・Storage の責務分離に従う。
- 関連しないリファクタリング、依存パッケージの追加、同期機能の拡張は行わない。ただしPDFを直接生成し、日本語を選択可能な文字として埋め込むため、利用者が承認したPDF限定の例外として`pdfmake` 0.3.11とNoto Sans JP Regular／Boldフォント・SIL OFL 1.1ライセンス文を同梱する。

## 機能ごとの確定範囲

### 1. ノート保存空間の分割

- 複数のノート保存空間を扱えるようにする。
- 保存空間ごとに、SQLite、Markdown、WebDAV 接続・同期設定、ロックを独立して管理する。
- 保存空間は以降のロック、インポート、エクスポートの基盤として先に実装する。
- 既存データの安全な扱いと、SQLite・Markdown・WebDAV・単一書き込みの整合性を優先する。
- 内部管理ディレクトリ、設定画面からの選択、切替時再起動の実装契約は [`../storage-spaces.md`](../storage-spaces.md) を正とする。

### 2. ロック機能

- 保存空間、ノートブック、ノートをそれぞれ単体でロックできるようにする。保存空間のロックは全ノート、ノートブックのロックは配下のノートへ継承する。複数のロックが重なる場合は、すべてを解除した起動中だけ本文を利用できる。
- 保存空間ごとのロック設定は「設定 > 保存場所」の下部にある保存空間設定で行い、ノートブック・ノートは通常画面3ペインの編集ポップアップから名前・タイトルとあわせて設定する。「設定 > ロック」では現在設定されているロックの確認、解除、パスフレーズ変更を行う。
- 保存空間がロックされた状態で起動した場合は、本文を読み込むServiceを起動せず、専用の解除画面を表示する。
- ロック中のノートまたはノートブックを選択した場合は、対象と継承元を含む未解除ロックを共通ダイアログで順に解除してから選択を続行する。キャンセル時は選択状態を変更しない。
- 自動ロックは解除時点からの固定時間方式とし、既定はアプリ終了時のみとする。設定候補は1分、5分、15分、30分、60分で、閲覧・編集などの操作では期限を延長しない。期限前の保存に失敗した場合はロックを保留して再試行する。
- ノートブック名・ノートタイトルなどのメタデータは平文のまま保持し、Markdown本文だけを認証付き暗号化して保存する。パスフレーズそのものや復号鍵は永続化せず、復号鍵は解除した起動中のメモリだけに保持する。
- 保護対象ノートは、解除済みの起動中であってもAIのコンテキスト、履歴、成果物に使用しない。既存の対象AI記録がある場合は、ロック設定前に件数を表示し、利用者の明示確認後だけ削除する。
- 平文を送信済みの既存同期先は、ロック設定前に切断する。暗号化本文を同期する形式はこのスコープで拡張しないため、本文ロックを持つ保存空間の同期設定・実行は拒否する。暗号化同期を導入する際は、新しい同期先へ切り替える。
- ロック中はノート本文の閲覧を防止し、即時ロック時は画面上の編集中本文を消去する。既存の OS 単一書き込み用 `datalock` はユーザー向けのロック機能ではないため、別の機能として扱う。

### 3. md・txt・HTMLからインポート

- Markdown（`.md`）、テキスト（`.txt`）、HTML（`.html` / `.htm`）をノートとして取り込めるようにする。
- タイトルの決定方法は「自動」「ファイル名」「先頭見出し」「メタデータ」から、インポートするファイル一括で選択できるようにする。自動では、Markdown／テキストの先頭行ATX見出し、HTMLの最初の可視`h1`、HTMLの`title`または`meta[name="title"]`、ファイル名の順に決定する。選択した情報がない場合はファイル名へフォールバックする。
- 保存先の初期値は最上位階層とし、ノートブックの選択または新規作成もできるようにする。
- 複数ファイルをインポートする場合は、1ファイルを1ノートとして取り込む。
- HTMLの変換は「HTML変換ルール（確定）」に従う。
- 添付ファイルの取り込みは本スコープに含めない。

### 4. HTMLエクスポート

- アクティブな単一ノートの保存済み本文を、UTF-8、`lang="ja"`、CSP、埋め込み固定CSSを含む自己完結HTMLとして直接出力する。
- dirty draftを既存保存laneでflushし、保存ダイアログ選択後にGo側でrevision、Markdown snapshot、ロック状態を再検証する。HTML断片はGo側のallowlistで再サニタイズし、外部CSS、JavaScript、画像を含めない。
- 保護された解除済みノートは、暗号化領域外に平文を出力する明示警告と確認を必須とする。
- 添付ファイルを含むエクスポートや複数ノートの一括出力は本スコープに含めない。
- 詳細契約は [`../note-export.md`](../note-export.md) を正とする。

### 5. PDFエクスポート

- アクティブな単一ノートの保存済み本文から、A4縦のPDFファイルを直接生成して出力する。
- `pdfmake` 0.3.11と同梱Noto Sans JP Regular／Boldを使い、日本語を選択・検索可能な文字として埋め込む。画像データは出力せず`alt`文字列だけを保持する。
- HTMLと同じflush、revision・Markdown snapshot・ロック再検証、平文警告、ネイティブ保存ダイアログ、原子的保存の契約に従う。Go側はBase64復号後のPDFについてヘッダー、終端、32 MiB上限を検証する。
- 添付ファイル、複数ノート、用紙設定、PDF暗号化は本スコープに含めない。
- 詳細契約は [`../note-export.md`](../note-export.md) を正とする。

### 6. グローバルショートカット

- アプリウィンドウ内の操作をキーボードから実行できるようにする。OS全体で、Atlas Noteが非アクティブなときにも反応するシステムホットキーは対象外とする。
- ノート本文の「元に戻す」「やり直す」は既定をそれぞれ`Ctrl + Z`、`Ctrl + Y`とする。この2操作を含め、すべてのショートカットを「設定 > ショートカット」で変更・解除・初期化できるようにする。
- 既定割り当てを持つアプリ操作は、新規ノート`Ctrl + N`、検索欄へ移動`Ctrl + F`、設定を開く`Ctrl + ,`とする。同期、インポート、常に最前面、テーマ、編集モード、AIワークスペースの各操作は初期状態では未割り当てとする。
- キー設定はversion付きの端末ローカルUI設定として`localStorage`へ保存し、保存空間、SQLite、Markdown、WebDAVへ保存・同期しない。重複、文字入力の標準操作との衝突、修飾キー不足、不正な保存値は検証する。
- 「元に戻す」「やり直す」は開いているノート本文のMarkdown／Rich編集履歴だけを対象とし、既存のautosave経路へ新しい下書きとして渡す。保存済みrevisionの巻き戻し、別ノートの履歴、Agent適用結果の巻き戻しには使わない。
- 本文履歴は起動中のメモリだけに保持し、ノート切替、本文の外部再読込、競合下書きの破棄、編集モード切替、ロック、アンマウントで破棄する。
- 詳細契約は [`../keyboard-shortcuts.md`](../keyboard-shortcuts.md) を正とする。

### 7. 自動バックアップ・バックアップ復元

- アクティブな保存空間のSQLiteと`notes/`以下を、設定されたアーカイブルートの`.atlasnote-backups/<spaceID>/`へ24時間間隔で自動バックアップする。既定ONの端末UI設定、最大10世代の自動世代、最大3世代の復元前安全用世代を持つ。
- 各世代はmanifest、ファイルサイズ、SHA-256、SQLite integrity、schema versionを検証し、symlink、パス traversal、マニフェスト外ファイルを拒否する。Credential Store、保存空間台帳、同期復旧領域はバックアップへ含めない。
- 復元はプレビューと5分間有効の確認トークンを必要とする。検証済みstageを作成して次回起動へ引き渡し、データロック取得後かつSQLite open前に現行データを安全用バックアップ・rollbackへ退避してswapする。途中終了時はフェーズマーカーから再開し、失敗時はrollbackする。
- 同期復旧との同時適用を禁止し、dirty draftのflush、同期・AI・インポート・エクスポート・本文ロック・保存空間切替のbusy確認を既存ライフサイクルへ接続する。
- 詳細契約は [`../backup-restore.md`](../backup-restore.md) を正とする。

## HTML変換ルール（確定）

HTMLは安全な文書構造だけをMarkdownへ変換する。raw HTML、属性、CSS、スクリプトおよび外部リソースはMarkdownへ残さず、インポート時にも実行・取得しない。

| HTML要素 | Markdownへの変換 |
| --- | --- |
| `h1`〜`h6` | 対応するレベルの見出し（`#`〜`######`） |
| `p`、`div`、`section`、`article`、`main`、`header`、`footer`、`figure`、`figcaption` | 子要素を段落として保持 |
| `br` | Markdownのハード改行（末尾2空白 + 改行） |
| `strong`、`b` / `em`、`i` / `del`、`s`、`strike` | それぞれ `**太字**`、`*斜体*`、`~~取り消し線~~` |
| `blockquote` | 各行を `> ` で始める引用 |
| `ul`、`ol`、`li` | 入れ子を維持したMarkdownリスト。`ol` の `start` 属性は開始番号として保持 |
| `input[type="checkbox"]` がリスト項目内にある場合 | `- [ ]` / `- [x]` のチェックリスト。他のフォーム要素は変換しない |
| `code` | インラインコード。内容にバッククォートがある場合は必要な長さのバッククォートで囲む |
| `pre > code` | 改行・空白を保持したコードフェンス。`language-<name>` の安全な言語名だけをフェンスへ付与 |
| `hr` | `---` |
| 単純な `table` | 先頭行をヘッダーとするGFMテーブル。セル内の改行と `|` はエスケープする |
| `a[href]` | `https`、`http`、`mailto`、`tel`、`atlasnote`、またはページ内アンカー（`#...`）だけをMarkdownリンクとして保持。その他のURLはリンク化せず文字列だけを保持 |
| `img` | 添付・外部画像は取り込まず、`alt` の文字列だけを保持 |

- `title`、`meta[name="title"]`、最初の可視`h1`は、選択したタイトル決定方法に応じてタイトル候補として扱う。`head`内のその他の内容は本文に含めない。
- `thead`、`tbody`、`tfoot`、`tr`、`th`、`td`は単純な表の行・セルとして扱う。`rowspan`、`colspan`、不均一な列数を含む表は、行ごとのプレーンテキストへフォールバックし、不正なMarkdown表を生成しない。
- `script`、`style`、`noscript`、`template`、`iframe`、`object`、`embed`、`svg`、`canvas`、`video`、`audio`、`source`、`track`、`base`、フォーム要素は内容を含めて破棄する。
- `hidden`属性を持つ要素とその子孫は、本文と先頭`h1`の候補から破棄する。属性値にかかわらず`hidden`属性の存在だけで非表示とし、CSSの`display`／`visibility`、class、`aria-hidden`は評価しない。
- 未対応の要素は属性をすべて破棄し、子要素の安全な変換結果または可視テキストだけを保持する。コメント、DOCTYPE、`class`、`style`、イベント属性は保持しない。
- HTMLエンティティは文字へ復号し、`pre` / `code`以外の連続する空白は通常のテキスト空白として正規化する。
- HTMLパーサーは多少のタグ欠落を許容して変換する。ただし変換後に可視テキストも構造要素もない場合は、空ノートを作成せずインポートエラーにする。

- 追加テーマ
- マルチウィンドウ
- Mermaid対応
- 数式（LaTeX）
- カレンダービュー
- AIエージェント

- 機能ごとに既存のテスト方針に沿った確認を追加し、関連する品質チェックを通過させる。
